# Power BI Dashboard Specification

Power BI is not embedded in Streamlit. Connect Power BI Desktop to the CSV
files under `data/exports/powerbi/`, generated by
`scripts/export_powerbi_data.py`. Re-run that script (and refresh in Power
BI) whenever new predictions/alerts/experiments should be reflected.

## Exported files

| File | Columns | Source |
|---|---|---|
| `equipment_health.csv` | machine, timestamp, probability, risk_level | `predictions` joined to `machines` |
| `predictions.csv` | prediction_id, machine, prediction_timestamp, failure_probability, predicted_class, risk_level, model_version_id, created_at | `predictions` |
| `alerts.csv` | alert_id, machine, timestamp, risk_level, status, message | `alerts` joined to `machines` |
| `active_models.csv` | model_version_id, version, model_type, dataset_id, threshold, created_at, active | `model_versions` where active=1 |
| `model_performance.csv` | experiment, model, metric, value | `reports/experiments/*/​*_metrics.json` |

All exports handle an empty database gracefully (header-only CSV), so the
script is safe to run before any predictions exist.

## Recommended report pages

1. **Executive Equipment Health Overview** -- KPI cards (total machines,
   active alerts, high-risk count) from `equipment_health.csv` +
   `alerts.csv`.
2. **High-Risk Machines** -- table of `equipment_health.csv` filtered to
   `risk_level = "High Risk"`, sorted by `probability` descending.
3. **Risk Trends** -- line chart of `probability` over `timestamp`,
   sliced by `machine`, from `predictions.csv`.
4. **Alert Analysis** -- `alerts.csv` grouped by `status` and `risk_level`.
5. **Prediction History** -- full table/export from `predictions.csv`.
6. **Model Comparison** -- bar chart of `value` by `metric` and `model`
   from `model_performance.csv`, one visual per experiment.
7. **Feature Importance** -- not yet exported as CSV (SHAP importances are
   currently viewed in the Streamlit Explainability/Model Performance
   pages); add a `feature_importance.csv` export if a Power BI view is
   required later.
8. **Maintenance Events** -- populate once a genuine maintenance-events
   log (not currently in the source CMMS export beyond PM/WO snapshots) is
   imported into the `maintenance_events` table.

## Known gaps (honest, not fabricated)

Pages 7 (Feature Importance) and 8 (Maintenance Events) have no populated
export yet because the underlying data/computation isn't wired into the
export script -- do not build placeholder Power BI visuals against
non-existent data; add the export first.
